2 语音全链路 · 两代架构演进
第一代 ESP32 直连智谱 AI → OLED
ai_service.cpp 限制回复「5 个英文单词」→ "OK" / "I don't know" → 无信息量
为什么？OLED 128×64 内容区仅 48px 高，不加限制 AI 回复溢出屏幕
第二代 ESP32 → MQTT → Web DeepSeek Agent → MQTT → ESP32
agent.js：think → tool_call → observe 多轮推理 + 8 Function Calling 工具
回复质量大幅提升，但延迟 7-12s，ESP32 端 15s 超时偶尔被截断
核心创新：流式 base64 编码
ESP32-C3 仅 400KB RAM，无法一次性构建 128KB 的 WAV+base64 JSON body
→ streamBase64Concat()：WAV头+PCM → 480B 分块 → 边编码边 HTTPS 发送
WAV头与PCM必须作为连续流处理，否则中间产生错误'='填充符 → API 解析失败
延迟拆解： 录音 2s → base64
~0.2s → TLS 握手
0.3-0.8s → 上传
0.5-2s → ASR
0.3-1.5s → Agent
2-8s 总 7-12s
3 MQTT 通信：阻塞重连 + Broker IP 硬编码
问题一：同步阻塞
PubSubClient.connect() ← 同步阻塞！ Broker 不可达时 TCP 超时数秒 → 主循环完全卡死 → 按键/OLED/倒计时/看门狗停摆
ESP32-C3 单核 RISC-V，无法 xTaskCreatePinnedToCore
当前缓解：5s 冷却窗口 + 已连接时 loop() 非阻塞
问题二：IP 硬编码
// config.h:77 #define MQTT_BROKER_IP "172.21.1.146"
PC DHCP 换 IP → Broker 不可达
→ 每 5s 触发阻塞重连
→ 用户感觉"设备一直在找 MQTT"
解法
最快补救 Broker IP 存入 NVS Flash (Preferences)，OLED 交互式输入，无需重新烧录
根治 换 AsyncMQTTClient (回调非阻塞，不影响主循环) 或 FreeRTOS 任务隔离 MQTT
